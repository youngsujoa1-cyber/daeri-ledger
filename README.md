# 대리장부 (Daeri Ledger)

대리운전·탁송 기사를 위한 **진짜 순수익 장부** 안드로이드 앱.
플랫폼 수수료와 건당 보험료를 정확히 빼서 "손에 남는 돈"을 보여주고, 영업일 기준(새벽 콜)으로 장부를 묶는다.

- 패키지: `com.youngsu.daeriledger` (debug: `com.youngsu.daeriledger.debug`)
- 버전: 1.0.23 (versionCode 24)
- minSdk 26 / targetSdk 35, Kotlin 2.0.21, AGP 8.7.3, Material 3
- 기본 테마: **다크** (야간 운행용 고대비), 라이트/시스템 전환 가능

## 핵심 기능

### 1. 플랫폼별 정확한 수수료
| 플랫폼 | 기본값 | 비고 |
|---|---|---|
| 카카오T · 티맵 · 핸들 | 20% | 앱에 수수료 차감 후 금액이 보임 (`netShown=true`) → 받은 금액을 넣으면 총매출을 역산 (20,000원 → 총매출 25,000원, 수수료 5,000원) |
| 로지 · 콜마너 · 아이콘 | 20% | 설정에서 % 수정 · 입력값이 총매출(수수료 떼기 전) |
| 개인콜 | 0% | |
| **팁 · 경유비** | **20%** (모든 플랫폼 공통) | 설정에서 `개인콜` 바로 아래에서 조정. 받은 팁을 이 %로 역산 — 로지 45,000 + 받은 팁 10,000 → 팁 총액 12,500 · 총액 57,500 · 수수료 11,500(요금 9,000 + 팁 2,500) · 순수익 46,000. `0%`면 팁에 수수료를 떼지 않음 |

- 대리/탁송 구분, **건당 보험료**(대리 기본 1,500원 / 탁송 2,500원, **카카오T·티맵은 적용 안 함**), **고용·산재·세금 %**(기본 0%)까지 반영 — 입력 화면에는 둘을 합쳐 **`보험&세금`** 줄로 보여 주고, 그 아래 `건당 0원 + 3.3% 1,485원` 처럼 내역을 나눠 적습니다(v1.0.20)
- 입력 중 실시간 미리보기: `총매출(팁 포함) − 수수료 − 보험&세금 = 진짜 순수익`. 팁·경유비를 적으면 `팁 · 경유비 (받은 10,000원 / 20%) +12,500원` 처럼 역산된 총액이 함께 보이고, 수수료 줄에 `플랫폼 수수료 20% · 팁·경유비 20%` 로 적용 %가 표시됩니다

### 2. 영업일 기준 (기본 낮 12시)
02:30 새벽 콜은 전날 영업일 장부로 들어간다. 기준시각은 0~23시에서 변경 가능.

### 3. 3초 입력
플랫폼 칩 → 금액 칩(1.5·2·2.5·3·4·5만) → 저장. **출발지 · 도착지 · 경유** 순서로 적고(경유는 비워도 됨 · 카드에서는 늘 `출발 → 경유 → 도착` 순서로 보임), 팁·경유비, **특이사항**(대기비·경유·손님 요청 등)은 같은 화면에서 바로 적고, 건당 보험료만 `▾ 상세 입력 (건당 보험료)`를 펼쳐 고깁니다. 적어 둔 특이사항은 **오늘·달력·미수금 카드의 `카카오T [대리] [후불]` 배지 줄 오른쪽**에 바로 보여서, 카드를 열지 않아도 확인됩니다.

### 4. 지출 · 미수금
셔틀비·대중교통·식대·프로그램비·월보험료·기타. 결제는 **현금 · 후불 · 미수금** 세 가지 — 손님에게 나중에 받는 카드·포인트 결제가 `후불`, 현장에서 받지 못한 콜이 `미수금`(미수금 화면에서 1탭 "입금 완료", 되돌리기 지원)입니다.

### 5. 휴무일
일하지 않은 날은 **휴무**로 표시해 둡니다.
- **달력**: 고른 날 옆 `휴무` / `휴무 해제` 버튼으로 하루를 바로 표시, 칸 안에 회색빛 `휴무` 표가 보입니다
- **오늘**: 헤더의 `휴무` 버튼으로 1탭 표시, 선택한 날 요약은 `휴무일 · 일하지 않은 날` 로 바뀝니다
- 휴무는 통계의 `일한 날`(콜이 있는 날)에 들어가지 않고, 기간 요약에 `휴무한 날 N일` 로 따로 표시됩니다
- 휴무로 표시해 둔 날에 콜을 기록하면 그 칸은 기록(수입·콜 수)을 우선 보여줍니다

### 6. 오늘 / 달력 / 콜밭 / 통계
- **오늘**: 총수입(헤드라인)·순수익·지출·수수료·콜수, 일일 목표 진행바(총수입 기준), 시간당·콜당 순수익
- 운행 카드(오늘·달력·미수): 첫 줄 = **경로(출발 → 도착, 경유를 적었으면 출발 → 경유 → 도착)**, 아랫줄 = **플랫폼 · 대리/탁송 · 결제(현금/후불/미수금)**, 오른쪽 **큰 녹색 숫자 = 총수입**, 그 아래 회색 줄 = **실수익** (경로를 안 적은 기록은 첫 줄에 플랫폼 이름)
- **달력**: 월간 그리드에 영업일별 총수입(녹색)·콜수, 이번 달 총수입/실제수익, 날짜 탭 → 그날 전체 내역이 바로 보이도록 자동 스크롤
- 오늘·달력의 하루 내역은 **기록 순서(이른 시간 위 → 늦은 시간 아래)** 로 보여줍니다
- **콜밭**: 전국 콜밭 **1,223곳**(직접 정리 318 + 카카오맵 즐겨찾기 `기사 추천` 905) 참고 목록 — 출처 칩 없이 **하나의 콜밭 목록**(위치 기반 거리순) + **검색창**(지역·역·동·주소 실시간 필터) + **시·도 칩**(전체·서울·경기·인천·부산 …) + 길찾기. 예전 `콜포인트1`·`콜포인트2` 는 `기사 추천` 하나로 합쳤고 **탁송 콜밭(357곳)은 목록에서 뺐습니다**.
  - **기사님 공용 제보 (v1.0.16 · 5명 기준)** — Firebase Firestore(`spot_reports`)에 인증 없이 제보를 쌓고 앱이 집계합니다. 같은 자리(반경 150m)에 **서로 다른 기기 5명 이상**이 콜밭을 제보하면 `기사 제보` 배지(`기사 5명 제보 · 10분 전`)로 모든 사용자 목록에 함께 보이고, 같은 자리에 **5명 이상이 없어진 곳으로 신고**하면 모든 사용자 화면에서 그 반경의 콜밭이 숨겨집니다. 4명까지는 아무 변화도 없습니다. 서버 규칙은 8개 칸 형식만 검사하므로 등록은 `kind="콜밭"`, 삭제 신고는 `kind="삭제"` 로 같은 스키마를 씁니다(`SpotCloud.kt` · 집계는 `SpotAggregate.kt`, 5분 캐시·최근 30일·최대 500건, 네트워크 실패 시 조용히 로컬 목록만)
  - **없어진 곳 처리 (카드 길게 누르기, v1.0.19 UI 개선)**: 길게 누르면 안내문 같은 목록 대신 **테두리·둥근 모서리·아이콘·한 줄 설명이 있는 카드 버튼**으로 떠요(`dialog_spot_actions.xml`) — 🙈 `내 화면에서만 숨기기`(기존 `hiddenSpotIds`, 목록 위 ‘되돌리기’로 복구) / 🚨 `없어진 곳 신고`(주황 테두리, 5명 이상 신고 시 전체 기사님 목록에서 삭제) / 🗑️ `내 콜밭 삭제`(내가 추가한 콜밭일 때만, 붉은 테두리). 신고하면 서버로 `kind="삭제"` 가 가고 **내 화면에서는 바로 숨겨집니다**
  - **`+ 콜밭 추가`** (화면 오른쪽 위, v1.0.19): 창을 열면 **현재 GPS 위치를 자동으로 잡아** 좌표와 시·도/지역 칸을 미리 채우고(위치를 못 잡으면 `위치를 아직 못 잡았어요 — 지도에서 골라 주세요`), 버튼 하나 **🗺️ 지도에서 위치 바꾸기** 로 지도에서 고른 좌표·주소로 덮어씁니다. 장소명(필수)·구분(대리/탁송)·피크·메모를 적어 저장하면 콜밭 목록에 바로 들어가 검색·거리순·길찾기·숨기기가 똑같이 동작합니다. 추가한 콜밭은 `내 콜밭` 배지가 붙고 카드를 길게 눌러 **삭제**할 수 있으며, **JSON 백업에도 함께** 들어갑니다
  - **콜밭 지도 (v1.0.21)**: 콜밭 탭 위쪽(지역 칩 아래)에 **카카오맵 카드**(기본 240dp, `크게`로 460dp까지) — 지금 고른 **지역 칩·검색·숨김을 그대로 따라** 좌표가 있는 콜밭을 **핀**으로 찍습니다. **내 콜밭은 앰버 핀**, 그 밖의 콜밭은 민트 핀, 내 위치는 파란 점이며 처음 한 번은 내 위치(없으면 목록 첫 콜밭)를 중심으로 뜨고 `내 위치`로 다시 맞춥니다. 핀을 누르면 이름·지역·피크·거리·메모와 `길찾기` 가 지도 아래 카드로 뜨고, 빈 지도를 누르면 닫힙니다. 목록이 1,200곳이라 **핀은 최대 200곳**(목록 순서 = 내 콜밭·가까운 순)만 찍어 버벅이지 않게 했고, 지도를 드래그·줌할 때는 바깥 스크롤이 터치를 가로채지 않습니다(`SpotsMapPage.kt` · `SpotsScreen.setupMap`). 카카오 키가 없거나 SDK 를 못 띄우면 카드에 안내와 `다시 시도`가 뜨고 앱·목록은 그대로 동작합니다
  - **핀이 안 보이던 버그 수정 (v1.0.22)** — v1.0.21 은 지도는 떴지만 **핀이 한 개도 안 찍혔습니다**. 앱이 핀 목록을 `setSpots([{…}])` 처럼 **배열 객체**로 넘기는데 지도 HTML 이 무조건 `JSON.parse(json)` 을 해 `"[object Object]"` → `SyntaxError` → 빈 목록이 됐기 때문입니다. 이제 `setSpots` 가 **배열·JSON 문자열 둘 다** 받고(앱은 따옴표로 감싼 문자열로 보냄), 지도가 아직 만들어지기 전에 들어온 목록도 기다렸다 찍습니다. 핀은 18px · `box-sizing:border-box` · 흰 2px 테두리 · 가운데 흰 점으로 다듬어 카카오맵 위에서 한눈에 보입니다(`SpotsMapPage.kt` · `SpotsScreen.pushMapSpots`). 실제 JS 로 `setSpots([...])` 200곳 → 핀 200개인지 검사하는 하네스는 `tools/map-pin-check/check_pins.py`
  - **👑 운영자(관리자) 모드 (v1.0.23)** — 설정 화면 **맨 아래 `앱 버전`을 5번 연속 탭**(2초 넘게 쉬면 횟수 초기화)하면 암호 입력창이 뜨고, `local.properties` 의 `ADMIN_PASS` 와 맞으면 운영자 모드가 켜집니다. 켜져 있으면 ① `+ 콜밭 추가` 창에 `👑 운영자 모드: 등록 시 5명 대기 없이 바로 전체 공개` 배지가 뜨고 저장한 콜밭이 **다른 기사님 앱에도 즉시**(`👑 운영자` 배지) 올라가며, ② 콜밭 카드를 길게 누르면 붉은 카드 **`👑 운영자: 전체에서 바로 삭제`** 가 생겨 **기본·기사 추천·공용 제보 콜밭 어떤 것이든** 반경 150m 안이 모든 기사님 앱에서 5명 대기 없이 사라집니다. 다시 버전을 5번 누르거나 정보의 `운영자 모드` 줄에서 끌 수 있고, 끄면 일반 기사용 **5명 기준이 그대로** 돌아옵니다. 서버 규칙(8칸 형식)을 바꾸지 않으려고 운영자 제보는 `deviceHash` 자리에 **암호로 만든 32자 16진수 운영자 해시**(`SpotAggregator.adminDeviceHash` — 일반 기기 해시와 같은 형식)를 넣고 `kind` 는 일반 제보와 같은 `콜밭`/`삭제` 를 씁니다 — 암호가 비어 있는 오픈소스 빌드는 운영자 제보를 만들지도, 알아보지도 못합니다(`SettingsScreen.onVersionTap`·`SpotCloud`·`SpotAggregate`, 테스트 `tools/logic-check`)
  - **중복 섹션 제거 (v1.0.21)** — 화면 위쪽의 `내가 추가한 콜밭` 카드 목록(금색 테두리)을 없앴습니다. 같은 내 콜밭이 아래 `콜밭 목록` 에 `내 콜밭` 배지로 거리순으로 이미 보이기 때문입니다. 삭제는 `콜밭 목록` 의 내 콜밭 카드를 길게 눌러 🗑️ `내 콜밭 삭제` 로 그대로 됩니다(목록 아래 안내문에도 한 줄 적어 둠). `숨긴 콜밭 N곳 · 되돌리기` 줄·지역 칩·`+ 콜밭 추가` 는 그대로입니다

- **통계**: 기간 요약(큰 숫자 = **총수입**, 그 아래 실수익·수수료·보험·지출·손에 남은 돈), 플랫폼별 수익/콜수 비교(콜당 실수익 포함), 요일·시간대 패턴, 지출 분석, 인사이트 — 금액은 모두 Long 으로 계산해 전체 기간이 5억을 넘어도 비중이 뒤집히지 않습니다

### 7. 백업 · 광고
- Room 대신 표준 SQLite(직접 스키마) + SAF 기반 **CSV 내보내기**, **JSON 백업/복원**(설정·콜밭(구분·지역 포함)·**휴무일**·**경유지** 포함). DB v4 — 기존 11,876건과 저장해 둔 콜밭은 `ALTER TABLE ADD COLUMN` 마이그레이션으로 그대로 남고 새 칸만 기본값으로 채워집니다
- **타 앱 백업 가져오기**: 대리 가계부(`dcb_teras.zip` / `.db`)의 T_CALL·T_CASH 를 읽어 운행 기록으로 옮깁니다 (중복 자동 제거, 한 트랜잭션 벌크 저장). 원본의 `CALL_OFF_CHK = 1` 행은 그날 일하지 않았다는 표시라 **휴무일**로 함께 가져옵니다
- AdMob 하단 배너: Google 공식 테스트 ID, `ads/AdConfig.kt` + `AndroidManifest.xml` 두 곳만 교체하면 실제 광고로 전환
- **통계 탭 전면 광고**: 통계 탭에 들어갈 때 전면 광고 1회, **3분 쿨다운**(첫 진입은 바로). 앱 시작 시 미리 받아 두고 닫히면 다음 광고를 미리 받음. 광고가 없거나 오프라인이면 기다리게 하지 않고 통계 화면을 그대로 보여줌 (`ads/InterstitialHelper.kt`)

### 공용 콜밭 제보 키 (저장소에 올리지 않음)

Firebase 웹 API 키는 소스에 적지 않습니다. `local.properties`(저장소 제외, `.gitignore`)에 한 줄을 두면
`app/build.gradle.kts` 가 `BuildConfig.FIREBASE_API_KEY` 로 넣어 줍니다.

```properties
# local.properties
sdk.dir=/workspace/buildenv/android-sdk
FIREBASE_API_KEY=여기에_Firebase_웹_API_키
KAKAO_JS_KEY=여기에_카카오_JavaScript_키
ADMIN_PASS=여기에_운영자_모드_암호
```

같은 이름의 환경 변수(`FIREBASE_API_KEY`)를 써도 됩니다. 키가 비어 있으면 앱은 공용 제보를 조용히 건너뛰고
로컬 콜밭 목록만 쓰므로 빌드 자체는 실패하지 않습니다. Google Cloud 콘솔에서 이 키를
**Cloud Firestore API 전용**으로 제한해 두세요(공개 저장소에 노출된 적이 있는 키는 재발급을 권장).

카카오 **JavaScript 키**(developers.kakao.com 앱 `1665700`)도 같은 방식으로 `KAKAO_JS_KEY` 에 넣습니다.

**운영자 모드 암호**(`ADMIN_PASS`)도 `local.properties` 에만 둡니다(저장소 제외). 값이 비어 있으면 설정의
버전을 5번 눌러도 잠금이 풀리지 않습니다. 앱은 이 암호로 만든 운영자 해시로만 운영자 제보를 알아보므로,
공개 저장소에는 어떤 형태로도 암호가 올라가지 않습니다.
지도 HTML 은 이 키로 **등록된 JavaScript SDK 도메인**(`https://youngsujoa1-cyber.github.io`)을 기준 주소로 열리므로,
카카오 콘솔의 JavaScript 키 → JavaScript SDK 도메인에 그 주소가 등록되어 있어야 합니다.
키가 비어 있으면 지도 피커는 OpenStreetMap 타일 지도로 동작합니다.

## 광고 교체 방법
1. `ads/AdConfig.kt`의 `USE_TEST_ADS = false`, `BANNER_UNIT_ID`를 실제 단위 ID로 변경
2. `ads/AdConfig.kt`의 `PROD_INTERSTITIAL_UNIT_ID`를 AdMob 에서 만든 **전면 광고 단위 ID** 로 변경
3. `AndroidManifest.xml`의 `com.google.android.gms.ads.APPLICATION_ID`를 실제 앱 ID로 변경

## 참고
- 콜밭 정보는 지역 특성과 기사님들의 지도 즐겨찾기를 정리한 참고 자료이며, 카카오T·로지 등 플랫폼의 실시간 콜 수량이 아닙니다.
- 공용 제보 서버는 Firebase **Spark(무료)** `daeri-ledger-spots` · Firestore `spot_reports` 입니다. 인증 없는 공개 쓰기라 규칙이 형식·크기만 제한하며(수정·삭제 불가), 집계는 앱이 합니다. 개인정보는 `ANDROID_ID` 를 SHA-256 으로 돌린 32자 기기 해시만 씁니다.
- 모든 기록은 기기 내부 SQLite에만 저장됩니다.
- 👑 운영자 모드 암호는 APK 안 `BuildConfig.ADMIN_PASS` 로 들어갑니다(앱 안에서만 쓰는 잠금이라 서버 로그인이 아닙니다). 앱을 배포하면 암호도 함께 배포되므로, 운영자 삭제를 외부에 막아야 하는 상황이 되면 암호를 바꿔 다시 빌드하고 Firestore 규칙에서 운영자 해시를 검사하는 쪽으로 옮기는 것이 안전합니다.
